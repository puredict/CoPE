# Occurrence-sensitive learned formal gate preregistration

Date: 2026-08-04  
Status: frozen before manifest generation, provider calls, or outcomes

## Question

Does a compact occurrence-addressed CoPE delta improve first-pass generation
of a canonical recurring commitment update relative to both a generic neutral
transaction and a Tang-inspired governed affected-scope delta?

This is a symbolic learned-interface experiment. It is not embodied evidence
and is independent of the stopped task-7 controller development.

## Fixed population

- 40 deterministic recurring-goal cases;
- ten ordered triples of distinct objects drawn from the fixed seven-object
  basket vocabulary;
- recurrence depths 1, 2, 3, and 4 per triple;
- each pre-state contains the complete alternating history needed for a
  critical update from intermediate occurrence `k` to recurring occurrence
  `k+1`;
- the satisfied done commitment and every superseded occurrence remain in the
  common input.

## Arms and calls

Five arms receive byte-identical common recovery input and provider settings:

1. occurrence-addressed CoPE typed delta;
2. occurrence-aware neutral JSON-path transaction;
3. occurrence-aware governed affected-scope/full-record delta;
4. occurrence-aware FSR-PC complete semantic state;
5. occurrence-aware full remaining-task replan.

One zero-retry call per case/arm gives exactly **200** provider calls. Arm order
is balanced by five-way rotation. Model, temperature, seed, token limits,
timeout, contracts, manifest, and normalized request hashes are frozen before
outcomes. A credential-free cold preflight must build all 200 requests with
zero provider calls.

## Outcomes

Primary per-cell success requires JSON parse, native-schema validation,
materialization, equality to the canonical occurrence state, preserved
history, one active chain tip, correct occurrence `k+1`, and correct compiled
directive. No repair or second draw is allowed.

Co-primary controls are neutral and governed. CoPE must beat **both** with:

- Holm-adjusted exact paired p-value `< .05` within the two-control efficacy
  family;
- paired risk difference at least `+0.15`;
- no excess history/invariant failures;
- Holm-adjusted exact sign p-value `< .05` within the two-control locality
  family and median proposal-byte reduction at least 20%.

FSR-PC and full replan are descriptive secondary controls and cannot rescue a
neutral or governed tie/loss. Provider timeout, HTTP/transport outage, or
ambiguous interrupted call invalidates the run rather than becoming method
evidence.

## Claim rule

Passing is evidence only for a learned occurrence-sensitive interface and
compactness under this model/prompt distribution. It does not establish
embodied recovery, architecture novelty, unique assurance, or cross-model
generality. A tie against either primary control is a method-paper NO-GO.

## Execution gate

No call may occur until the manifest, oracle five-arm capability gate, cold
request preflight, analyzer tests, crash-recovery runner, secure environment
credential, and one separately recorded smoke cell all pass. Pasted chat
credentials are not stored or reused.
