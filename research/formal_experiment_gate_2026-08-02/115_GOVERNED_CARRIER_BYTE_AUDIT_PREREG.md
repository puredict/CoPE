# Governed-control carrier and contract byte audit preregistration

Date frozen: 2026-08-04 (Asia/Shanghai)

## Question

How much smaller is the CoPE minimum occurrence-addressed carrier than an
equally capable Tang-inspired governed delta, neutral JSON-path transaction,
complete semantic state and full remaining-task replan on the assigned
dependent interruption transitions?

## Cases

Use exactly the four cases in
`manifests/sequential_persistence_gate_v2.csv`, with event 2 constructed from
the event-1 committed state.  This yields eight transition instances.

## Arms

- CoPE typed minimum update;
- neutral JSON-path transaction;
- governed affected-scope forest/blackboard delta;
- FSR-PC complete semantic state;
- full remaining-task replan.

All oracle carriers must first materialize to the same canonical next state and
directive.  The governed contract must be frozen in a separate module and must
not change the historical four-arm formal contracts.

## Measurements

For each transition and arm report:

- canonical compact JSON UTF-8 proposal bytes;
- output-contract UTF-8 bytes;
- proposal field/address count using an arm-specific deterministic definition;
- ratio to the complete-state carrier for the same transition.

Report medians, ranges and per-pair win counts.  Do not report tokenizer cost,
provider prompt tokens or latency because no provider is called.

## Interpretation boundary

This is deterministic representation accounting.  A CoPE byte win is expected
by construction and can support only a narrow compact-carrier claim.  It cannot
establish learned validity, semantic correctness, safety, latency, general
compression optimality or novelty.  Contract bytes must be reported alongside
proposal bytes because a small output may require a longer instruction.

Credentials, provider calls, GPUs, simulator states and reserved task states
are forbidden.
