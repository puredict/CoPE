Old cache key
-------------
The affected code cached a file digest using the resolved path and these stat
fields: st_dev, st_ino, st_size, st_mtime_ns, st_ctime_ns. The before/after stat
comparison used the same fields. These observations show that changed file bytes
can retain the entire key on this host. A cached digest can therefore be stale.

Interpretation and correction constraint
----------------------------------------
This is an observed cache-integrity defect, not grounds to weaken the test or
insert a sleep. Rapid writes were not distinguishable by the selected stat
fields on this host, despite their nanosecond API representation. The evidence
does not establish a universal timestamp resolution for every ext4 filesystem.

The safe correction identified here is to remove the stat-only digest cache and
read/hash actual bytes at each required validation boundary. Stat checks remain
useful for detecting some changes during a read, but are not proof that bytes
are unchanged. No stronger immutable-file guarantee was established during this
diagnostic. File permissions or advisory locks alone would not prove immutability
of files controlled by a writer.

The root task subsequently reported removing the cache and adding a deterministic
regression test with identical mocked stat fields for different file contents.
The fix and its validation belong to their separate code/test records. This
diagnostic does not claim that a formal protocol or model run passed.

Performance constraint
----------------------
Always reading/hashing files incurs I/O and CPU work proportional to their byte
size. Repeated validation of large checkpoints may materially slow execution.
No full-checkpoint throughput or formal-run latency benchmark was performed in
this diagnostic. Performance must not be improved by accepting stale digests.
