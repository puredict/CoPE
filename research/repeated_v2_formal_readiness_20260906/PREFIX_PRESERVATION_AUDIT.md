# CPU prefix and interruption-preservation audit

This evidence collection is partial and stopped fail-closed. Across four versioned stages, four distinct task0 initial-state cells received one oracle prefix attempt each. Three produced a stable, released first-goal prefix. No physical prefix was replayed. Sixteen planned task/state cells were never attempted and are not failures.

The stages returned 797 CPU environment controls in total:197 in the original task0/state0 prefix,400 for new state1/state2 attempts in V3, and200 for state3 in V4. V2 stopped before any new control. The controller uses privileged simulator geometry and these controls are never clean learned-policy calibration.

V3 evaluated seven existing candidate events independently on each of task0 states0 and1. All14 target applications returned with their mechanical/fresh-observation checks. Four paired setup applications were separately counted. Twelve of14 immediate samples retained the completed first goal. Both target-object-displacement candidates made that same protected goal false, which shows candidate/prefix incompatibility and does not establish whole-family or task infeasibility. No-go clearance and gentle-preference activation each retained the goal for five fresh zero-motion controls in both states: four bounded post-event preservation witnesses. These results do not certify collision safety, semantic trigger windows, recovery, the persistent-preference metric, or complete event-family feasibility.

The original stage stopped before its first event because a returned observation cache and a forced post-restore observation differed by0.629795 micrometres at the EEF while the complete flattened physical state was byte-identical. A separate zero-control diagnostic confirmed that the forced observation matches the authoritative EEF site. V2 then stopped with zero new work because a Python tuple was compared directly with its equivalent JSON array. V3 corrected that representation comparison and retained its exact source hash.

V3 later stopped because an explicit extra `sim.forward()` changed four free-joint quaternion floating-point values by one ULP (`1.1102230246251565e-16`) while time, qvel, task predicates and the authoritative EEF check remained valid. V4 removed that unnecessary second forward and recorded a stable state3 prefix, then stopped before an event because the existing `set_init_state` restore performed the same quaternion normalization and the deliberately exact byte-restore guard rejected it. The guard was not relaxed, and the attempted cells were not replayed.
